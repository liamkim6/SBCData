## 1. 배경

전면적인 보상(리워드) 체계를 도입하기 전에, 저비용·저리스크로 보상의 효과를 검증할 수 있는 선행 테스트가 필요합니다. 확정된 안은 다음과 같습니다.

> 첫 번째 박스 수령자가 **첫 리뷰를 작성하면 20크레딧($20 가치)**을 지급하고, 이 크레딧을 **다음 박스 큐레이션의 애드온 구매 단계**에서 사용할 수 있게 한다.

이 테스트가 우선순위로 합의된 이유:

- **리텐션 임팩트가 가장 큰 지점 공략**: 구독 커머스에서 이탈이 가장 큰 구간은 첫 박스 → 2번째 박스 전환이다. "다음 박스에서 쓸 수 있는 크레딧"은 2회차 결제를 유지할 명시적 이유를 만든다.
- **전면 보상 체계의 선행 신호**: 포인트/등급제 같은 전체 시스템을 만들기 전에, "리뷰 보상이 실제로 작성·재결제 행동을 바꾸는가"를 최소 기능으로 검증한다. E1의 크레딧 원장은 [PRD 03 포인트 원장](03-review-reward-gamification.md#91-백엔드--포인트-원장리뷰레벨)의 선행 최소 구현이다.
- **리뷰 데이터 확보**: 첫 박스 리뷰(평점·텍스트)는 E2 추천 모델과 커머셜 큐레이션의 원료 데이터가 된다.
- **애드온 습관 형성**: 크레딧으로 애드온 구매를 경험시키면, 이후 유료 애드온 부착률 상승을 기대할 수 있다.
- **추천 실험(E2)과의 시너지**: 크레딧으로 애드온을 고르는 선택 데이터는 추천 모델 학습·평가에 재사용된다.

## 2. 목표와 비목표

### 목표

1. 크레딧 인센티브가 **첫 리뷰 작성률**을 올리는지 검증
2. 크레딧 제공이 **M1→M2 결제 전환율**을 개선하는지 검증
3. 크레딧 애드온 경험이 **이후 유료 애드온 부착률**을 높이는지 검증
4. 크레딧 1건당 비용($20 × 지급률 × 사용률) 대비 증분 매출로 **단위 경제성** 추정 → 전면 보상 체계([PRD 03](03-review-reward-gamification.md))의 예산 근거 마련

### 비목표

- 포인트 적립·등급제 등 전면 보상 체계의 설계 (본 테스트 결과 이후 → [PRD 03 — 리뷰 리워드 게이미피케이션](03-review-reward-gamification.md))
- 애드온 구매 화면의 추천 로직 개선 (E2 범위 — 본 테스트에서는 기존 로직 고정)
- 기존 구독자(2박스 이상 수령자) 대상 리워드
- 2번째 이후 리뷰에 대한 반복 보상 (PRD 03 범위 — 본 테스트는 **첫 리뷰 1회 한정**)

## 3. 가설

| ID | 가설 | 검증 지표 |
|---|---|---|
| H1 | 첫 박스 수령자에게 "첫 리뷰 작성 → 다음 박스 애드온용 20크레딧" 오퍼를 주면 M1→M2 결제 전환율이 오른다. | M1→M2 전환율 (Primary) |
| H2 | 크레딧으로 애드온을 경험한 사용자는 3번째 박스에서 유료 애드온 부착률이 더 높다. | M3 유료 애드온 부착률 (Secondary) |
| H3 | 크레딧으로 인한 증분 매출(전환 개선 + 애드온 매출)이 크레딧 비용을 상회한다. | 사용자당 증분 마진 (Secondary) |
| H4 | 크레딧 오퍼는 첫 리뷰 작성률을 올린다. | 첫 리뷰 작성률 실험군 vs 대조군 (Secondary — PRD 03 배점 설계의 근거) |

## 4. 실험 설계

### 4.1 구조

```
첫 박스 결제 완료 (배정 트리거)
        │  user_id 해시 기반 랜덤 배정 (50:50)
        ├──────────────────────────────┐
   [대조군 C]                      [실험군 T]
        │                              │
   박스 수령 2주 후                 박스 수령 2주 후
   리뷰 요청 메일 (오퍼 없음)        리뷰 요청 메일 + "리뷰 쓰면 20크레딧" 오퍼
        │                              │
   리뷰 작성해도 크레딧 없음         Shelf에서 첫 리뷰 작성 완료 → 20크레딧 지급
        │                              │ 다음 박스 애드온 구매 단계에서
        │                              │ 사용 가능 크레딧 모달 노출
        ▼                              ▼
   첫 리뷰 작성률 ──────────── 비교 ── 첫 리뷰 작성률 (H4)
   M2 결제 여부 ───────────── 비교 ── M2 결제 여부 (H1)
   M2/M3 애드온 부착 ──────── 비교 ── M2/M3 애드온 부착 (크레딧 사용분 구분, H2)
```

- **배정 단위**: user_id (해시 기반, salt는 실험 코드 `E1_FIRST_REVIEW_CREDIT`)
- **배정 시점**: 첫 박스 결제 완료 이벤트 발생 시 1회
- **배정 비율**: 대조군 50 : 실험군 50
- **처치 정의**: 리뷰 요청 메일은 **양 군 모두 발송**(수령 D+14)하되, 실험군 메일에만 크레딧 오퍼를 포함한다 — 측정 대상을 "리뷰 요청" 효과가 아닌 **크레딧 인센티브** 효과로 분리하기 위함. 대조군의 리뷰 작성자에게는 크레딧을 지급하지 않는다.
- **ITT 원칙**: 실험군 배정자가 리뷰를 쓰지 않거나 크레딧을 사용하지 않아도 실험군으로 분석

### 4.2 크레딧 사양

| 항목 | 사양 |
|---|---|
| 크레딧 내용 | 20크레딧 ($20 가치, 1크레딧 = $1) |
| 단위 정책 | **본 테스트는 1크레딧 = $1 고정.** 전면 보상 체계(PRD 03)에서는 100P = 10센트로 단위를 세분화해 재무 부담·리스크를 분산하고 지급 조건을 잘게 나눈다 (환산: 1크레딧 = 1,000P — [PRD 03 §3.1](03-review-reward-gamification.md#31-이원-트랙-원칙)) |
| 지급 조건 | **첫 리뷰 작성 완료** (최소 기준: 별점 + 텍스트 — 상세 기준은 오픈 이슈) |
| 사용처 | 다음 박스 큐레이션의 **애드온 구매 단계**에서 결제 금액 차감 |
| 사용 조건 | 다음 박스 결제(구독 유지)가 전제 — 스킵/해지 시 사용 불가 |
| 유효 기간 | TBD (안: 지급 후 2 결제 주기) — 부분 사용 허용 여부와 함께 오픈 이슈 |
| 중복 정책 | 계정당 1회(첫 리뷰 한정), 재가입 사용자는 제외 (어뷰징 방지) |
| 회수 정책 | 첫 박스 전액 환불 또는 리뷰 삭제/검수 반려 시 크레딧 REVOKED |
| 소멸 안내 | 만료 72시간 전 미사용자에게 리마인드 1회 |

### 4.3 사용자 플로우 (실험군)

1. **첫 번째 박스 큐레이션 완료** → 결제·배송 (기존 경험 동일)
2. **박스 수령 완료 2주 후(D+14) 리뷰 요청 메일 발송**: "리뷰 남기고 다음 박스에서 쓸 수 있는 20크레딧 받으세요"
3. **메일 CTA → Shelf 진입 → 첫 리뷰 작성 이벤트 완료 → 20크레딧 지급** (Shelf = 수령 제품 보관함 페이지: 받은 제품 목록에서 제품별 리뷰 작성 진입)
4. **Shelf 페이지에서 참여 완료 상태와 지급받은 크레딧 확인 가능** (미작성 시 작성 유도 상태 유지)
5. **다음 박스 큐레이션 진행 시 애드온 구매 단계에서 "사용 가능 크레딧 20 ($20 가치)" 모달 노출** → 적용 시 결제 금액 차감, 주문 요약에 사용 내역 표기
6. 미작성 상태로 메일 발송 7일 후 → 리마인드 1회. 크레딧 만료 72시간 전 → 소멸 리마인드 1회

> 대조군은 1–2번까지 동일하되 메일에 크레딧 오퍼가 없으며, Shelf에서 리뷰를 작성해도 크레딧이 지급되지 않는다.

## 5. 지표

실험군 효과는 `메일 도달 → 리뷰 작성 → 크레딧 지급 → 크레딧 사용 → 재결제`의 퍼널을 거치므로, 단계별 지표를 함께 판독합니다.

| 구분 | 지표 | 정의 | 목표(초안) |
|---|---|---|---|
| **Primary** | M1→M2 결제 전환율 | 첫 박스 결제자 중 2번째 박스 결제자 비율 | 상대 +10% 이상 |
| Secondary | 첫 리뷰 작성률 (H4) | 메일 발송자 중 첫 리뷰 작성 완료 비율 — 실험군 vs 대조군 | 대조군 대비 유의 개선 |
| Secondary | 리뷰 요청 메일 오픈율 / CTR / Shelf 진입률 | 퍼널 헬스체크 | 오픈율 30%↑ (헬스체크) |
| Secondary | 크레딧 사용률 | 지급자 중 다음 박스 애드온 구매에 크레딧을 사용한 비율 | 40% 이상 (헬스체크) |
| Secondary | M3 유료 애드온 부착률 (H2) | 3번째 박스 결제 건 중 유료 애드온 포함 비율 (크레딧 사용분 제외) | 대조군 대비 개선 |
| Secondary | 사용자당 증분 마진 (H3) | (전환·애드온 증분 매출 마진) − ($20 × 지급률 × 사용률 상당 원가) | > 0 |
| Guardrail | 해지율, 스킵률, CS 티켓 비율 | [공통 가드레일](../experiments/00-experiment-overview.md#23-가드레일-지표-모든-실험-공통) 참조 | 악화 없음 |
| Guardrail | 크레딧 예산 소진 | 지급 크레딧 상당 원가 누계 | 사전 승인 예산 이내 |
| Guardrail | 평점 분포 왜곡 | 실험군 평점이 대조군 대비 유의하게 상향(보상發 인플레) | 평균 +0.3★ 이내 |

> 리뷰 작성률이 낮으면(< 15%) 크레딧 효과 부재가 아니라 **전달 실패**(메일 미도달·Shelf 진입 이탈)일 수 있으므로, 메일 오픈율·CTR·Shelf 진입률을 헬스체크로 분리해 함께 봅니다.

## 6. 기능 요구사항

### 6.1 크레딧 발급·관리 (백엔드)

- [ ] R1. **크레딧 원장** (append-only): `entry_id, user_id, type(EARN/REDEEM/EXPIRE/REVOKE), amount, balance_after, reason_code(E1_FIRST_REVIEW), ref_id(review_id/order_id), created_at, expires_at` — [PRD 03 §9.1 포인트 원장](03-review-reward-gamification.md#91-백엔드--포인트-원장리뷰레벨)의 **선행 최소 구현**으로, 스키마를 호환되게 설계해 PRD 03에서 승계한다
- [ ] R2. 지급 트리거: **첫 리뷰 작성 완료 이벤트** 수신 시 실험군에만 자동 지급 (계정당 1회)
- [ ] R3. 만료 처리: 유효기간 기준 배치 만료
- [ ] R4. 회수 처리: 첫 박스 전액 환불 또는 리뷰 삭제/검수 반려 시 크레딧 REVOKED
- [ ] R5. 주문 연동: 애드온 결제 시 크레딧 차감 라인아이템 처리 및 `entry_id` 연결 (정산·원가 추적용), 주문 환불 시 차감분 복원

### 6.2 프론트엔드

- [ ] F1. **Shelf 페이지**: 수령 제품 목록, 제품별 리뷰 작성 진입, **참여 완료 상태·지급 크레딧 잔액 표시**
- [ ] F2. 리뷰 작성 플로우: 별점 + 텍스트(+사진), 작성 완료 시 크레딧 지급 확인 피드백
- [ ] F3. **애드온 구매 단계 크레딧 모달**: "사용 가능 크레딧 20 ($20 가치)" 노출, 적용/미적용 선택
- [ ] F4. 주문 요약·영수증에 크레딧 사용 내역 표기
- [ ] F5. 크레딧 상태별 화면 처리 (지급 전 / 사용 완료 / 만료 / 회수)
- [ ] F6. 대가성 고지: 크레딧 지급 대상 리뷰에 고지 라벨 (PRD 03 §6.3과 동일 정책, 문구는 법무 확인)

### 6.3 CRM

- [ ] C1. 리뷰 요청 메일: 박스 **수령 완료 D+14** 트리거, 양 군 발송 — 실험군에만 크레딧 오퍼 문구/CTA 포함
- [ ] C2. 미작성자 리마인드 (메일 발송 7일 후 1회) 및 크레딧 만료 72시간 전 리마인드
- [ ] C3. 실험군/대조군 간 그 외 CRM 메시지 동일 유지 (효과 오염 방지 — 대조군에 별도 프로모션 금지)

| `box_order_completed` | box_seq, addon_count, addon_revenue, credit_amount_used(nullable) |

> `review_submitted`의 sku_id·rating은 E2 피처 파이프라인 및 [PRD 03 §9.4](03-review-reward-gamification.md#94-데이터이벤트-트래킹) 스키마와 정합을 맞춘다.

## 7. 표본 크기와 기간

표본 크기는 기준 전환율에 따라 달라지므로 아래는 산식과 예시입니다. **실험 시작 전 데이터팀이 실제 기준치로 확정해야 합니다** (오픈 이슈).

- 검정: 두 비율 z-검정, 양측 α=0.05, 검정력 80%
- 예시 (H1): 기준 M1→M2 전환율 55%, 목표 상대 +10%(→60.5%) 탐지 시 그룹당 약 **1,300명**, 총 약 2,600명
- 기준 전환율 40%, 상대 +10%(→44%) 탐지 시 그룹당 약 **2,300명**
- H4(첫 리뷰 작성률)는 기준선이 낮을수록(예: 10~20%) 동일 상대 효과 탐지에 더 큰 표본이 필요할 수 있으므로, 기준 리뷰 작성률 확인 후 H1과 함께 표본을 재계산한다

**기간**: `모집 기간(월간 신규 첫 박스 결제자 수 기준으로 산출) + 2 결제 주기(M2 결제 확인) + 1 결제 주기(H2의 M3 애드온 부착 확인)`. 예: 월 신규 3,000명이면 모집 약 1개월 + 관찰 2~3개월 = **총 3~4개월** (H4는 메일 발송 후 1개월 차, H1은 2개월 차에 1차 판독 가능).

## 9. 분석 계획

1. **0차 판독 (H4)**: 첫 모집 코호트의 메일 발송 + 30일 후. 첫 리뷰 작성률 두 비율 z-검정 — PRD 03 배점 설계의 근거 데이터.
2. **1차 판독 (H1)**: 마지막 모집 코호트의 M2 결제 마감 + 7일 유예 후. 두 비율 z-검정.
3. **2차 판독 (H2, H3)**: M3 결제 마감 후. H3는 `(실험군 ARPU − 대조군 ARPU) × 마진율 − $20 × 지급률 × 사용률 상당 원가`로 사용자당 증분 마진 추정.
4. **하위 분석 (탐색적)**: 가입 채널, 리뷰 작성 여부(작성자 vs 미작성자 — 셀렉션 주의), 첫 박스 만족도(리뷰 점수), 피부 타입별. 사전 등록되지 않은 하위 분석은 참고용으로만 사용.
5. **SRM 체크**: 시작 48시간 내, 이후 주간.
